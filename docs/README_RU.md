# Reticulum ESP-NOW Mesh -- Прошивка

Прошивка mesh-сети на основе ESP-NOW для микроконтроллеров ESP32, обеспечивающая подключение к сети Reticulum через BLE и UART интерфейсы. Позволяет организовать автономную зашифрованную mesh-связь с использованием приложений Sideband, Columba и других Reticulum-совместимых клиентов.

## Архитектура

```
Телефон (Sideband/Columba)       ESP32 Клиент                ESP32 Ретранслятор          ESP32 Клиент              Телефон
+-------------------+          +------------------+        +------------------+        +------------------+     +-------------------+
| Reticulum Stack   |<--BLE-->| KISS протокол    |<-ESP-->| Reticulum        |<-ESP-->| KISS протокол    |<-->| Reticulum Stack   |
| LXMF сообщения    |  NUS    | ESP-NOW v2       | NOW    | Transport Stack  | NOW    | ESP-NOW v2       |BLE | LXMF сообщения    |
+-------------------+         +------------------+        +------------------+        +------------------+    +-------------------+
```

Система состоит из трех типов прошивки:

- **Client** -- BLE мост между телефоном с Reticulum и ESP-NOW mesh сетью
- **Retranslator** -- транспортный узел, маршрутизирующий и ретранслирующий пакеты
- **UART Client** -- последовательный мост между ПК с Reticulum и mesh сетью

Все узлы обмениваются данными по ESP-NOW v2.0 с поддержкой 802.11 Long Range, обеспечивая до 500 м прямой видимости при размере полезной нагрузки 1470 байт.

## Поддерживаемое оборудование

| Плата | Чип | Дисплей | BLE | Client | Retranslator | UART |
|-------|-----|---------|-----|--------|-------------|------|
| ESP32-C3 DevKit + OLED | ESP32-C3 | SSD1306 72x40 | 5.0 | Да | Да | Да |
| LilyGO T-Display | ESP32 | ST7789 135x240 | 4.2 | Да | Да | Да |
| ESP32-S3 DevKitC | ESP32-S3 | Нет | 5.0 | Да | Да | Да |
| ESP32 DevKit | ESP32 | Нет | 4.2 | Да | Да | Да |
| ESP32-WROVER DevKit | ESP32 | Нет | 4.2 | Да | Да (4 МБ PSRAM) | Да |
| ESP32-CAM | ESP32 | Нет | 4.2 | Да | Нет | Нет |
| ESP32-C6 DevKitC | ESP32-C6 | Нет | 5.0 | Да | Да | Да |
| ESP32-S2 Saola | ESP32-S2 | Нет | Нет | Нет | Да | Да |

Примечание: на платах ESP32-S3 DevKitC встроенный RGB NeoPixel LED (GPIO 48) требует замыкания паяльной перемычки. Найдите маленькую площадку с маркировкой "RGB" рядом со светодиодом и замкните её припоем. Без этого светодиод работать не будет.

Варианты ретранслятора ESP32-S3 с PSRAM:
- **N16R8 / N8R8** (8 МБ octal PSRAM): до 4096 маршрутов
- **N4R2 / N8R2 / N16R2** (2 МБ quad PSRAM): до 1024 маршрутов
- **Без PSRAM**: до 128 маршрутов

## Быстрый старт

### Необходимое ПО

- PlatformIO CLI (v6.1+) или VS Code с расширением PlatformIO
- USB кабель для целевой платы
- Для BLE клиента: телефон Android с приложением Sideband или Columba

### Платформа PlatformIO: pioarduino

Проект требует форк **pioarduino** платформы Espressif 32. Официальная платформа PlatformIO `espressif32` использует Arduino Core 2.x / ESP-IDF 4.x, который не поддерживает ESP-NOW v2.0 (полезная нагрузка 1470 байт). Форк pioarduino предоставляет Arduino Core 3.x на ESP-IDF 5.5 с полной поддержкой ESP-NOW v2.

Платформа настраивается автоматически в `platformio.ini`:

```ini
platform = https://github.com/pioarduino/platform-espressif32/releases/download/stable/platform-espressif32.zip
```

PlatformIO скачивает и устанавливает её автоматически при первой сборке. В большинстве случаев ручная установка не требуется.

#### Установка тулчейна (если автоустановка не работает)

На некоторых системах (особенно Windows с MSYS2/MinGW) автоматическая установка тулчейна может завершиться ошибкой:

```
ERROR: MSys/Mingw is not supported
idf_tools.py installation failed
```

**Исправление для RISC-V (ESP32-C3, ESP32-C6):**

1. Скачайте тулчейн вручную:
   - Перейдите на https://github.com/espressif/crosstool-NG/releases
   - Скачайте `riscv32-esp-elf-14.2.0_XXXXXXXX-x86_64-w64-mingw32.zip` (Windows) или соответствующий архив для вашей ОС
2. Распакуйте в каталог пакетов PlatformIO:
   ```bash
   # Windows
   cd %USERPROFILE%\.platformio\packages\toolchain-riscv32-esp
   # Распакуйте содержимое архива, затем переместите файлы на один уровень вверх:
   # Архив распаковывается в подкаталог riscv32-esp-elf/
   # Скопируйте содержимое riscv32-esp-elf/* в текущий каталог
   cp -r riscv32-esp-elf/* .
   ```
3. Проверьте: `bin/riscv32-esp-elf-g++ --version` должно работать

**Исправление для Xtensa (ESP32, ESP32-S2, ESP32-S3):**

Аналогичный процесс, но скачайте `xtensa-esp-elf-14.2.0_XXXXXXXX-x86_64-w64-mingw32.zip` и распакуйте в `toolchain-xtensa-esp-elf/`.

**Linux/macOS:** Автоматическая установка обычно работает. В случае ошибки используйте тот же подход с ручной загрузкой архива для вашей платформы.

#### Проверка установки

```bash
# Должна показать версию платформы pioarduino
pio run -e client_c3 --list-targets

# Первая сборка загружает все зависимости (может занять несколько минут)
pio run -e client_c3
```

Ожидаемый вывод платформы:
```
PLATFORM: Espressif 32 (55.x.x) > ...
PACKAGES:
  framework-arduinoespressif32 @ 3.3.x
  framework-arduinoespressif32-libs @ 5.5.x
```

Если версия framework показывает 2.x вместо 3.x, платформа pioarduino установлена некорректно.

### Сборка

```bash
# Клонирование репозитория
git clone <repository-url>
cd reticulum-espnow

# Сборка для ESP32-C3 клиента (по умолчанию)
pio run -e client_c3

# Сборка ретранслятора
pio run -e retranslator_c3

# Сборка UART клиента
pio run -e uart_c3
```

### Прошивка

```bash
# Прошивка подключенной платы (автоопределение порта)
pio run -e client_c3 -t upload

# Прошивка на конкретный порт
pio run -e client_c3 -t upload --upload-port COM24
```

### Мониторинг Serial

```bash
pio device monitor
```

Для прошивки UART клиента Serial используется для протокола KISS на скорости 921600 бод. Для мониторинга статуса используйте отдельный терминал или дисплей устройства.

## Настройка

Все параметры находятся в `include/board_config.h`.

### Канал ESP-NOW

```c
#define ESPNOW_CHANNEL  13      // WiFi канал (1-13)
```

Все узлы mesh сети должны использовать один и тот же канал. Используйте утилиту сканера каналов для выбора наименее загруженного канала.

### Режим Long Range

```c
#define ESPNOW_LONG_RANGE  1    // 1 = включен (по умолчанию), 0 = стандартный
```

Режим 802.11 LR удваивает дальность (~500 м прямой видимости) за счет снижения пропускной способности (512/256 Кбит/с вместо 1 Мбит/с). Поддерживается всеми вариантами ESP32 кроме ESP32-C2. Все узлы сети должны использовать одинаковую настройку.

### Интервал анонса транспорта

```c
#define TRANSPORT_ANNOUNCE_INTERVAL_MS  (2 * 60 * 60 * 1000UL)  // 2 часа
```

Зарезервировано для периодического реанонса ретранслятора в сети. В настоящее время не используется -- периодический реанонс отключен из-за проблем стабильности на ограниченном оборудовании. Ретранслятор анонсирует себя один раз при загрузке, что достаточно для одноуровневых ESP-NOW broadcast сетей, где все узлы слышат друг друга напрямую.

### Отладочная сборка

Сборка с подробным логированием Reticulum:

```bash
pio run -e retranslator_c3_debug
```

Релизные сборки используют уровень LOG_WARNING (минимальный вывод). Отладочные -- LOG_TRACE (полный подробный вывод).

## Управление кнопками

### BLE клиент (main_client.cpp)

| Действие | Длительность | Результат |
|----------|-------------|-----------|
| Двойное нажатие BOOT | 2 быстрых нажатия | Вкл/выкл дисплей и светодиоды (сохраняется) |
| Удержание BOOT 2+ сек | Отпустить после 2 сек | Режим BLE сопряжения |

### Ретранслятор (main_retranslator.cpp)

| Действие | Длительность | Результат |
|----------|-------------|-----------|
| Двойное нажатие BOOT | 2 быстрых нажатия | Вкл/выкл дисплей и светодиоды (сохраняется) |
| Удержание BOOT 5+ сек | Продолжать удерживать | Сброс к заводским настройкам (удаление идентификатора и маршрутов) |

### UART клиент (main_uart_client.cpp)

UART клиент работает в безголовом режиме (headless). Кнопки не используются. Последовательный порт полностью выделен для протокола KISS на скорости 921600 бод.

## Сопряжение BLE

### С приложением Sideband (Android)

1. Прошейте клиентскую прошивку BLE на плату
2. Включите плату -- она начнет BLE рекламу как "RNode XXXX" (XXXX = последние 2 байта MAC)
3. В Sideband перейдите в Настройки > Подключение > включите "Connect via RNode"
4. Перейдите в Hardware > RNode > отметьте "Device requires BLE"
5. Нажмите "Scan" -- устройство должно появиться
6. Нажмите для сопряжения -- 6-значный PIN появится на дисплее устройства (или в Serial для плат без экрана)
7. Введите PIN на телефоне
8. После успешного сопряжения Sideband покажет интерфейс RNode как активный

### Повторное сопряжение

Для сопряжения с другим телефоном:
1. Удерживайте кнопку BOOT 2+ секунды для входа в режим сопряжения
2. Существующие привязки будут очищены, реклама перезапущена
3. На дисплее отобразится "PAIRING...", светодиод замигает синим
4. Выполните шаги сопряжения с новым телефоном

### Платы без дисплея

На платах без дисплея (ESP32-S3, ESP32, ESP32-C6) PIN-код выводится в Serial каждые 10 секунд:

```
*** PAIRING PIN: 474567 ***
```

Подключитесь через USB Serial монитор на скорости 115200 бод. На платах ESP32-S3 с двумя USB портами PIN отображается на обоих.

## Настройка UART

### Конфигурация Reticulum

Добавьте в конфигурационный файл Reticulum (`~/.reticulum/config`):

```ini
[[ESP-NOW Serial]]
  type = RNodeInterface
  port = /dev/ttyUSB0
  speed = 921600
```

На Windows:
```ini
[[ESP-NOW Serial]]
  type = RNodeInterface
  port = COM11
  speed = 921600
```

UART клиент эмулирует протокол KISS RNode, поэтому Reticulum подключается к нему как к стандартному устройству RNode.

## Информация на дисплее

### SSD1306 OLED (72x40, ESP32-C3)

Дисплей показывает четыре строки:

**Клиент -- подключен:**
```
[*] RNode C6D4
TX: 1234
RX: 5678
32.5 C
```

**Клиент -- отключен:**
```
[O] RNode C6D4
TX: 0
RX: 0
28.1 C
```

**Клиент -- режим сопряжения:**
```
[O] RNode C6D4
PAIRING...
Connect from
phone now
```

**Клиент -- отображение PIN:**
```
PAIR PIN:
  474567
```

**Ретранслятор:**
```
[~] TRANSPORT
TX: 167
RX: 4521
31.2 C
```

Значки: [*] = BLE подключен (заполненный круг), [O] = BLE отключен (пустой круг), [~] = радио/транспорт

### ST7789 TFT (135x240, T-Display)

Та же информация, что и на OLED, но с цветовым кодированием:
- Зеленый круг и "BLE OK" = подключен
- Красный круг и "BLE --" = отключен
- Желтый = лучший канал / рекомендуемый
- Голубой = цифры PIN-кода сопряжения

### Переключение дисплея

Двойное нажатие кнопки BOOT включает или выключает дисплей. Состояние сохраняется в энергонезависимой памяти и переживает перезагрузки. При выключенном дисплее светодиоды также отключаются для снижения энергопотребления.

## Сброс к заводским настройкам (только ретранслятор)

Удерживайте кнопку BOOT 5 секунд для выполнения сброса:

1. Все данные NVS очищаются (настройки дисплея, флаг инициализации)
2. Файловая система форматируется (идентификатор Reticulum и все изученные маршруты удаляются)
3. Светодиод загорается красным во время процесса
4. Устройство автоматически перезагружается
5. При следующей загрузке генерируется новый транспортный идентификатор

Эта операция необратима. Ретранслятор появится в сети как новый узел.

### Первая загрузка

При первой прошивке ретранслятора (или после сброса к заводским настройкам):

1. Устройство определяет, что не было инициализировано
2. Файловая система форматируется для чистого хранилища
3. Генерируется и сохраняется новый транспортный идентификатор Reticulum
4. Устройство перезагружается в нормальный режим

Если питание пропадет во время первой загрузки, устройство загрузится нормально при следующей попытке с пустой файловой системой. Reticulum сгенерирует новый идентификатор автоматически.

## Известные ограничения

### Память ESP32-C3 ретранслятора

ESP32-C3 имеет 320 КБ SRAM без PSRAM. При интенсивном трафике анонсов (подключение к testnet, большие сети) транспортный стек microReticulum испытывает нехватку памяти из-за проблем управления памятью в upstream библиотеке. Ретранслятор на C3 рекомендуется для малых сетей (до 20 узлов). Для более крупных развертываний или подключения к testnet используйте ESP32-S3 с PSRAM.

### Известные ошибки microReticulum (upstream)

Следующие проблемы относятся к библиотеке microReticulum (не к данной прошивке):

- Структура `_held_announces` растет без ограничений при интенсивном трафике
- `_announce_table` использует `insert()` без `erase()`, допуская устаревшие записи
- Миграция таблицы маршрутов из heap в flash-хранилище не завершена

Эти проблемы задокументированы в проекте RTNode-HeltecV4. Патчи существуют, но требуют форка microReticulum.

### Периодический реанонс

Периодический реанонс транспортного узла (для обнаружения в цепочках с несколькими хопами) в настоящее время отключен из-за проблем стабильности с `Destination::announce()` на ограниченном оборудовании. Начальный анонс при загрузке работает корректно. Для одноуровневых ESP-NOW broadcast сетей это не влияет на работу, так как все узлы слышат друг друга напрямую.

## Устранение неполадок

### BLE устройство не видно на телефоне

- Убедитесь, что устройство включено и светодиод мигает (heartbeat)
- На Android 15+ включите "Показывать неподдерживаемые BLE устройства" в настройках разработчика
- Попробуйте удерживать BOOT 2 секунды для повторного входа в режим сопряжения
- Убедитесь, что другой телефон не подключен (одновременно допускается одно подключение)

### Sideband показывает "no unpaired RNodes"

- BLE имя устройства должно начинаться с "RNode " (с пробелом). Это устанавливается автоматически из MAC адреса
- Удалите сопряжение устройства в настройках Bluetooth Android, затем повторите сканирование в Sideband
- Убедитесь, что "Device requires BLE" отмечен в настройках RNode Hardware в Sideband

### Нечитаемый вывод Serial

- Проверьте скорость: 115200 бод для мониторинга, 921600 бод для данных UART клиента
- На платах ESP32-S3 оба USB порта выводят Serial данные. Подключитесь к любому из них
- Убедитесь, что терминал использует окончания строк CR+LF

### Дисплей остается черным

- Двойное нажатие кнопки BOOT -- дисплей может быть выключен (состояние сохраняется между перезагрузками)
- При первой прошивке дисплей по умолчанию включен

### Сброс к заводским настройкам не работает

- Удерживайте BOOT полные 5 секунд. Светодиод загорается красным при срабатывании сброса
- Если плата не реагирует, удерживайте BOOT при нажатии RESET, затем отпустите BOOT для входа в режим загрузки и перепрошивки

### ESP-NOW не соединяется между узлами

- Все узлы должны быть на одном канале (ESPNOW_CHANNEL в board_config.h)
- Все узлы должны использовать одинаковую настройку LR режима (ESPNOW_LONG_RANGE)
- Проверьте, что узлы находятся в пределах досягаемости (~200 м стандартный, ~500 м с LR режимом)
